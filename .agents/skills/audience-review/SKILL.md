# 成片观众体验检查

围绕三维拆解与机械因果核对具体时间点和真实视听。

只在用户显式调用时执行。按留存与完播、点赞、收藏、评论和关注审查。每条发现写明它可能怎样帮助或妨碍对应目标。以相同 MP4 的实际证据给出内容判断，发布后按项目复盘模板记录实际数据。

正式生产使用独立 `final-qa`。符合条件的 Neil 成片可走音频技术验收。本次观众体验审核按实际能力记录听到的内容和覆盖范围，缺少连续听审时仍可完成有证据支持的部分。

检查结果写在当前回复中。源视频和生产记录只读，可使用现有检查缓存和临时文件。禁止修改视频、重新生成配音、添加音乐或音效、重新渲染、派遣 Agent、启动 Producer 修复、调用生产门禁或改变任务状态。禁止预测平台推荐、具体完播率、点赞率或涨粉数。

## 确认视频

优先使用调用中给出的本地 MP4 路径，支持相对项目根目录的路径和带空格的引号路径。显式路径不可读或缺少视频流时，说明问题并请用户提供有效路径。

省略路径时，从当前对话和当前任务目录识别最近明确交付或标为成片的 MP4。任务记录和交付说明只用于确认版本。排除预览、样片、片段和对比视频。若任务或成片版本无法唯一确定，请用户提供路径。

## 检查实际音画

1. 用 `ffprobe` 确认所选 MP4 的总时长、视频流和实际播放音轨。优先用当前环境可用的能力以正常速度从头到尾观看和聆听，可分为连续且无遗漏的段落。复查开场、首个实质回答、关键动作、顿悟和结尾。所有时间码用原 MP4 的播放时间。音轨缺失时记录探测结果，继续检查画面。
2. 用 FFmpeg 按需检查实际音轨的截断、异常静音、响度波动和疑似削波。用成片的字幕出现时间和音轨中的语音区间核对时间轴，必要时提取对应片段。片段及测量时间换算回原 MP4。引用测量时注明范围和单位，引用静音检测时注明阈值。峰值偏高只用于定位疑似削波。
3. 需要静帧时运行 `UV_CACHE_DIR=/private/tmp/mechanical-video-next-uv-cache uv run python -m mechanical_video_next.qa_images "所选路径.mp4" --times 0 1 2 3`，使用实际路径和检查点秒数。每轮最多四帧和一张联系表，只读取返回的 WebP/JPEG `qa_path`。仅在实际读图后调用 `record_reads`。静帧支持该时刻的构图、字幕和零件状态，动作先后需有可定位的连续画面证据。

在报告第一节简述实际连续观看、实际聆听和同步核对的区间。每条结论标注时间码、具体依据和适用的证据类别。

- **实际听到**，注明确实听到的词、声音或变化。
- **实际看到**，注明可见的动作、字幕或零件状态。只有同一时段确实听到并做过对照，才标为 **实际看到并与声音核对**。
- **工具测量**，注明来自实际 MP4 的指标、检测或 ASR 定位及其适用区间。
- **根据文本或元数据推断**，注明来源与可验证的范围。Blueprint、配音文本、音频配置和 QA 报告仅用于定位或核对预期，审核以最终 MP4 为准。
- **无法确认（UNKNOWN）**，在覆盖说明中简述缺少的视听能力或区间。播放回执、完整解码、静帧、波形、响度和 ASR 仅支持各自范围的结论。继续审核可观察的画面、声音技术指标与观众体验。

## 按需定位旁白时间

已有证据足以确定时间码时，直接使用该证据。需要进一步定位会影响观众理解的关键讲解或字幕错位时，可用 Apple Silicon 上的 `mlx-whisper` 转写相关片段。ASR 与脚本的文字差异不构成发音问题，也不影响其余审核。将 `review_video` 设为选定 MP4，`review_range` 设为需要核对的起止秒数。多音轨时，按 `ffprobe` 的结果将 `-map 0:a:0` 改成对应的成片音轨。保留延迟起音前的静音，让转写时间码使用原视频时间轴。

```sh
review_video="所选路径.mp4"
review_range="8.4,11.2"
review_cache=/private/tmp/mechanical-video-next-uv-cache
review_tmp=$(mktemp -d /private/tmp/audience-review-asr.XXXXXX)
review_model=mlx-community/whisper-small-mlx
review_cached_model="$review_cache/whisper-small-mlx-45f3915"
if [ -f "$review_cached_model/config.json" ] && [ -f "$review_cached_model/weights.npz" ]; then
  review_model="$review_cached_model"
fi

ffmpeg -v error -copyts -start_at_zero -i "$review_video" -map 0:a:0 \
  -af 'aresample=16000:async=1:first_pts=0' -ac 1 -c:a pcm_s16le "$review_tmp/mix.wav" &&
UV_CACHE_DIR="$review_cache" HF_HOME="$review_cache/whisper-hub" \
  uv run --no-project --python 3.14.2 --with mlx-whisper==0.4.3 \
  mlx_whisper "$review_tmp/mix.wav" --model "$review_model" \
  --language zh --task transcribe --clip-timestamps "$review_range" --verbose False \
  --output-format json --output-dir "$review_tmp"
```

从 `mix.json` 取段落时间码作为定位线索。中文以外按实际语种设置 `--language`，不确定时省略以自动检测。工具不可用时用已有证据继续审核。

## 观众体验

有同状态 A/B 时，检查两版分别在什么时候让首次观看者定位施力、关键接触及结果。画面发动机、色调和镜头数量只能定位差异，观众体验判断绑定可见或可听的具体变化。

- **完播检查**。定位开场机械动作、核心问题和首次实质答案。逐段核对每次拆解新增了什么机械关系，音画节奏是否持续推进理解。结合开场声音、Neil 配音速度和停顿、字幕停留、动作观察时间及 BGM 对人声的影响，定位重复预告、无信息镜头、赶词或停滞的段落，判断哪里值得压缩、删除或调序。
- **点赞检查**。定位最有价值的「原来如此」瞬间，用一句观众能复述的话写出本集收获。核对零件、动作和结果是否在画面中可见，Neil 旁白是否讲清因果，必要的音效是否与接触、卡住或释放的时刻一致。指出哪些声画细节实际支持结论，哪些关系还需要更清楚的动作或镜头证明。
- **收藏检查**。定位可停看复习的结构、传动关系和设计取舍。确认同一机构能在连续画面或三维总览中对应到外观和内部动作。
- **评论检查**。核对实际影片、简介或置顶评论候选的问题是否来自同一个机械现象，是否自然引发经验、知识或选题反馈。已发表作品的真实评论按复盘模板回流，各自记录时间窗与事实依据。
- **吸粉检查**。核对本集是否完整兑现开场问题，定位能让观众期待持续看到「拆开机器、看懂工作原理」的段落。检查声音风格与结尾收束是否自然，答案之后是否承接到下一个具体机构或机械问题。核对生硬口播、弹窗、无关预告或突然截断是否打断兑现和承接。

## 声音和音画的检查线索

- **Audiogen Neil 配音**。检查旁白节奏、断句、停顿和重音是否帮助观众理解。对照知识难度检查语速、塞词、术语密度和原理是否说得清楚。只有用户明确指出读错的位置，或实际听审发现明显异常时，才针对该处听审发音。将确认的问题纳入对应的观众目标。
- **机械音效**。把开合、滑动、卡扣、弹簧、齿轮和碰撞与画面上的实际动作逐一对照。定位关键听觉反馈的缺失、延迟、与物理过程不符、过度夸张、重复或有廉价素材感的声音。判断哪些动作值得给出听觉重点，保留适合安静呈现的动作。
- **BGM**。检查音乐是否符合本集气质，开场、拆解、发现和结尾是否有自然的情绪变化。听查进入、退出、过渡、音量起伏，以及贯穿单曲是否使段落失去层次。核对音乐与人声、关键机械动作的平衡，判断什么位置值得降低音乐音量。无音乐也可以是成立的选择。
- **音画与字幕同步**。在同一时间轴核对机构露出、旁白关键词、字幕起止和发声、动作开始或接触与音效瞬态。定位解释结束后才发生的动作、旁白尚未讲完就切走的画面，或关键知识点观察时间不足的段落。核对顿悟所在的声画时刻能否让观众看懂因果。
- **整体听觉体验**。听查开头几秒、全片旁白是否单调、声音层次和呼吸感、人声清晰度、音乐或音效遮蔽、音量跳变、爆音、削波、异常静音、突兀剪切、底噪，以及结尾是否突然截断配音或音乐。用实测响度、峰值和异常区间辅助复核。

把发现写入最相关的增长目标。严重技术故障附时间码、证据和影响。BGM、音效和互动安排按本集需要取舍。实际数据使用 [抖音发布后复盘模板](../../../docs/douyin-post-review.md)，注明窗口与分母，缺失项保留 null。

## 比较当前任务的参考作品

查当前任务现有的 `viral-analysis` 或其他有时间码的观看记录。如果有确实观看过的优秀参考作品，比较已观看范围内可迁移的内容组织、节奏和视觉表达。将比较写在对应目标下，注明参考来源与时间段、成片对应时间段，以及这种方法在本片可能带来的帮助。沿用可迁移的方法，保留本集原创的分镜、措辞和视觉设计。用实际表达效果决定片段长度和剪辑节奏，保留有效的停顿和观察时间。参考仅有页面、静帧或未经核实的描述时，跳过观看比较。

## 回复格式

使用下面六个标题。五个目标各写简短结论和最能影响修改决策的实际观察。注明文件和视听覆盖，事实判断引用时间点或区间，例如 `00:08.400–00:11.200`。覆盖不全时，把发现和「未发现」限定在已观察或测量的区间。

**完播检查**

写明开场动作和声音、首次回答、冗余片段。相关修改引用末尾优先级序号。

**点赞检查**

写明「原来如此」瞬间、一句话收获、视觉证明和声音重点。相关修改引用末尾优先级序号。

**收藏检查**

指出可复习的结构与传动总结，核对可见范围和手机可读性。

**评论检查**

定位主要讨论话题及其机械依据，区分实际评论与创作期互动方案。

**吸粉检查**

写明本集兑现、持续的系列价值和下一个具体机构的承接。相关修改引用末尾优先级序号。

**最终修改优先级**

从五个目标中选全片最值得修改的问题，按对实际观众体验的影响排序，同一问题只列一次，最多三项。每项给出视频时间码、实际观察或测量依据、对应目标及对观众的潜在影响、具体修改动作和证据类别。有感知缺口时注明 UNKNOWN 的范围。证据只支持更少建议时按实际数量给出。仅由文本推断或未确认的发现留在相关目标内注明限制。

留存检查定位前 2 秒的可辨认物件及真实功能动作，并记录前 5 秒内的首次结果或实质因果推进。逐段判断观看任务，保留有实际观察依据的静态状态对照。结合精确 MP4 的 pacing 报告检查等待、重复与旁白错位。平台历史值用于设计下一次验证，具体镜头证据和待验证假设分别记录。
